# Sweep: whole repo (2026-10-19)

What this code does: skills (Markdown instructions), hooks and Node scripts
that run a size-scaled issue, plan, build, audit, ship flow in Claude Code and
OpenCode. The hooks run on every agent tool call; the scripts keep work-item
state in uncommitted plan files and talk to local, GitHub or Jira trackers.
Load assumed: one developer per machine, hooks on every tool call, several
sessions or worktrees on one repo at once, and repos that may be cloned from
someone else.

Read: hooks/, .opencode/plugins/, scripts/, skills/*/scripts/, tests/, all
28 SKILL.md files and their sibling docs, docs/DESIGN.md, docs/adr/.
Not read in full: jira.mjs request paths beyond what tests touch, codemap.mjs
past the first 60 lines, scripts/lib/routing.mjs.

Mechanical: `npm test` 103/103 pass; `npm run check` pass (routing 96.9%);
guard-it scan over the whole history clean (11 built-in rules; no
`.compliance-rules/`, no security policy, no dependencies).

## Findings

### Must

1. **A cloned repo's committed config can run commands and redirect Jira tokens** (`skills/track-it/scripts/config.mjs:70-110`, `hooks/lib/guard.mjs:45-52`, `skills/track-it/scripts/adapters/jira.mjs:28-40`)
   - **What this is:** `.do-it/config.env` in the repo is read after the user's own config and can set any key.
   - **Problem:** It can set `DO_IT_LINT_CMD`, which the hooks run with `shell: true` after the agent's first edit, and `JIRA_BASE_URL`, which receives the user's `JIRA_API_TOKEN` in the `Authorization` header. Only secret-looking keys warn. Validated: confirmed; ADR 0003 and 0004 do not cover untrusted repos.
   - **Fix:** Ignore command and endpoint keys (`DO_IT_LINT_CMD`, `JIRA_BASE_URL`, any future URL or command key) from project scope unless the user config trusts that repo root.
   - **If we skip it:** Opening an agent in an untrusted clone with hooks on (the default) is code execution and credential theft.

2. **A malformed `checks.json` blocks every edit in OpenCode and silently disables all checks in Claude Code** (`hooks/lib/checks.mjs:72,79,91,100`, `.opencode/plugins/do-it.mjs:28-57`)
   - **What this is:** `loadChecks` trusts each rule's shape; the OpenCode plugin has no try/catch and signals a block by throwing.
   - **Problem:** A rule with `"files": ".ts"` throws `rule.files.some is not a function`. Reproduced: Claude hook exits 0 ("failed open"), OpenCode `tool.execute.before` rejects, so the write is blocked. In Claude Code the same throw also drops session context and every built-in secret rule with only a stderr line.
   - **Fix:** Validate rule shape in `loadChecks` (drop non-objects, coerce `files` to an array, ignore bad severities with a warning); wrap each OpenCode hook body so an unexpected error allows.
   - **If we skip it:** One typo in a team's rules file stops all OpenCode edits, against the "hooks fail open" rule in AGENTS.md.

3. **The commit scan misses pathspec commits and `-a` before the first commit** (`hooks/lib/guard.mjs:65-100`)
   - **What this is:** Before `git commit`, the hook scans the staged diff (or `git diff HEAD` with `-a`).
   - **Problem:** `git commit -m x a.js` commits the unstaged working-tree `a.js`, but only `--cached` is scanned. With no commits, `git diff HEAD` exits 128, the error becomes `''`, and the commit is allowed. Validated: confirmed in a temp repo.
   - **Fix:** With pathspecs or `-i`/`-o`, diff those paths in the working tree; with no HEAD, diff against the empty tree (`EMPTY_TREE` in `changeset.mjs`).
   - **If we skip it:** Secrets written by a Bash command reach a commit unscanned.

### Should

4. **The local tracker will rewrite any `.md` file and drops list fields** (`skills/track-it/scripts/refs.mjs:15`, `skills/track-it/scripts/adapters/local.mjs:25-43`)
   - **What this is:** Any ref ending in `.md` is a local issue; `readIssue` keeps only flat `key: value` lines and `writeIssue` writes back only those.
   - **Problem:** `tracker.mjs comment docs/planning/x/README.md` (or `start` on an issue with a `labels:` list) silently drops the nested `phases:`/`audit:` block or the list. Plans are uncommitted (ADR 0002), so git has no copy.
   - **Fix:** Refuse refs outside `DO_IT_ISSUES_DIR`; refuse to write when the frontmatter had lines the parser skipped.
   - **If we skip it:** A wrong ref destroys a plan's progress record with no recovery.

5. **Plan and issue writes are not atomic, and `verify-phase` writes back a stale copy** (`skills/do-it/scripts/state.mjs:435`, `adapters/local.mjs:43`, `skills/do-it/scripts/work.mjs:224-241`)
   - **What this is:** Files are written in place with `writeFileSync`; `verify-phase` loads the item, runs the checks (minutes), then writes.
   - **Problem:** A kill or full disk mid-write leaves an empty plan; any `event` or `set` from another session during the checks is overwritten.
   - **Fix:** Write to a temp file and rename; re-read the item after the command, before the transition.
   - **If we skip it:** Lost progress in exactly the multi-session setup build-it's parallel mode creates.

6. **GitHub Enterprise URLs lose their host, so writes go to github.com** (`skills/track-it/scripts/refs.mjs:8-9`, `adapters/github.mjs:11,23`)
   - **What this is:** An issue URL is reduced to `owner/repo` and passed as `gh -R owner/repo`.
   - **Problem:** `https://ghe.corp/o/r/issues/5` acts on `github.com/o/r#5` when the user is logged in there; the comment on line 7 says GHE is supported.
   - **Fix:** Keep the host and pass `-R host/owner/repo`.
   - **If we skip it:** `close` or `comment` lands on an unrelated public repo.

7. **Parallel implementers record phases without the verification gate** (`skills/build-it/PARALLEL.md:58`, `skills/do-it/STATE.md:24,34`, `work.mjs:95-104,224-241`)
   - **What this is:** build-it's serial path uses `verify-phase`, which runs the checks and records only on exit 0; PARALLEL.md tells implementers to call `event phase-done <n> "<commands>"`, which records a self-declared pass.
   - **Problem:** The gate exists for the one mode most likely to skip checks. The rule also lives in work.mjs, though state.mjs says all transition rules live in `transition()`.
   - **Fix:** Point PARALLEL.md at `verify-phase`; make `phase-done` reachable only from it.
   - **If we skip it:** Parallel phases can be marked verified without running anything.

8. **DESIGN.md describes the per-phase-commit model that ADR 0002 reversed** (`docs/DESIGN.md:16-26,64,80-83,95,207-208,226-235`)
   - **What this is:** The design doc's lane table, state block, build-it output and ship-it steps.
   - **Problem:** It still has XS "→ commit", `status: ... | done`, `commit:` per phase, `jira:`, commit-it/verify-it, and "one or two commits"; STATE.md says there is no `done` status and ship-it closes after one commit.
   - **Fix:** Replace §3, §4 and §7 with short links to STATE.md, LANES.md and the ADRs, so the design doc stops keeping its own copy.
   - **If we skip it:** Anyone (or any agent) reading the design doc first learns the wrong model.

9. **Guardrail candidates are deleted before retro-it can read them** (`skills/ship-it/SKILL.md:85,92-93`, `skills/ship-it/DOCS.md:9-12`, `skills/retro-it/SKILL.md:17-20`)
   - **What this is:** prove-it writes "Guardrail candidates" into `audit-report.md`; ship-it offers `/retro-it <id>` after `work.mjs close`.
   - **Problem:** `close` deletes the planning directory and its audit report; DOCS.md does not carry the candidates anywhere.
   - **Fix:** Offer retro-it at the ship question, before close.
   - **If we skip it:** The feedback loop prove-it promises never runs.

10. **LANES.md and prove-it disagree on what audits lane S** (`skills/do-it/LANES.md:8`, `docs/DESIGN.md:200`, `skills/prove-it/SKILL.md:37-41`)
    - **What this is:** LANES says lane S runs "prove-it (Spec and Standards)"; prove-it's table runs Compliance in lane S too.
    - **Problem:** Two sources of truth for the reviewer matrix.
    - **Fix:** LANES names only `prove-it`; the matrix lives in prove-it.
    - **If we skip it:** An agent reading LANES skips the compliance review.

11. **Frontmatter is parsed three or four ways** (`skills/do-it/scripts/state.mjs:13-335,407-413`, `adapters/local.mjs:7-45`, `scripts/lib/skills.mjs:14-60`, `hooks/lib/context.mjs:53`)
    - **What this is:** Each module has its own split regex, quoting rule and CRLF handling.
    - **Problem:** CRLF fixes landed one copy at a time (three separate regression tests); finding 4 is one copy's limit.
    - **Fix:** One `frontmatter.mjs` (split/join, flat read/write); the plan codec and local tracker sit on it.
    - **If we skip it:** Each fix needs finding in each copy.

12. **guard.mjs and scan.mjs still re-implement changeset.mjs** (`hooks/lib/guard.mjs:84-99`, `skills/guard-it/scripts/scan.mjs:28-57`, `skills/do-it/scripts/changeset.mjs:25-45`)
    - **What this is:** New evidence for T41: `changeset.mjs` now exists but only work.mjs imports it.
    - **Problem:** Two more "diff -U0, keep `+` lines" loops, one git spawn per file (a 3,000-file commit passes the 15 s hook timeout), and scan.mjs reports `line: 0` for tracked files.
    - **Fix:** One `addedLines(base | 'staged')` from a single `git diff`, imported by both.
    - **If we skip it:** Wrong line numbers in reports, skipped scans on big commits.

13. **Tests depend on the developer's environment** (`tests/hooks.test.mjs:128,171`, `tests/hooks-regressions.test.mjs:22,98`, `tests/work.test.mjs:247,292,321`, `tests/scripts-regressions.test.mjs:26,107`)
    - **What this is:** Hook and plugin tests pass the real `process.env` and HOME; test commits do not disable signing or hooks.
    - **Problem:** `DO_IT_HOOKS=off`, `DO_IT_LINT_CMD`, a global `commit.gpgsign` or `core.hooksPath` turns the suite red; `git init -b` needs git 2.28+.
    - **Fix:** One test helper that sets a temp HOME and XDG dir, clears `DO_IT_*`, and sets `GIT_CONFIG_GLOBAL=/dev/null`.
    - **If we skip it:** CI (T1) and contributors see failures unrelated to their change.

14. **`npm run check` enforces less than AGENTS.md and SKILL-MECHANICS.md say** (`scripts/check.mjs:83`, `scripts/lib/routing.mjs:126-128`)
    - **What this is:** The docs say check enforces the skill rules.
    - **Problem:** A link from a skill to `../../docs/x.md` passes (it breaks after a symlink install); a missing "Use when", a non-`-it` name, or a new model-invoked skill with no routing entries all pass (the last is only a warning).
    - **Fix:** Fail on links that leave `skills/` and on missing routing entries; either enforce or stop claiming the rest.
    - **If we skip it:** The rules drift while the docs say they are checked.

15. **Skills tell subagents to start their own subagents** (`skills/prove-it/SKILL.md:33-39` → `skills/review-it/SKILL.md:57-60`; `skills/roadmap-it/SKILL.md:35-36` → `skills/look-it-up/SKILL.md:24-26`)
    - **What this is:** prove-it starts review-it as a subagent, and review-it starts two more; roadmap-it does the same with look-it-up.
    - **Problem:** On hosts where subagents cannot spawn subagents, the brief cannot run as written.
    - **Fix:** One rule in SKILL-MECHANICS.md: only the main context fans out; review-it and look-it-up run inline when already in a subagent.
    - **If we skip it:** prove-it's Spec and Standards review degrades unpredictably.

16. **Concurrent creates and partial publishes lose or duplicate issues** (`adapters/local.mjs:80-81`, `work.mjs:163-168`, `adapters/github.mjs:85-92`, `adapters/jira.mjs:122-135`)
    - **What this is:** Creates check `existsSync`, then write; publish creates children one at a time.
    - **Problem:** Two sessions logging the same title both write `fix-login.md`; a 429 halfway through publish throws away created refs, so the re-run duplicates them.
    - **Fix:** Write with `{flag: 'wx'}` and retry the suffix; return partial publish results so a re-run resumes.
    - **If we skip it:** Lost issues locally, orphan issues in GitHub or Jira.

### Nice

18. **The same structural checks live in four places** (`skills/design-it/SKILL.md:37-39`, `skills/prove-it/ARCHITECTURE.md:8-18`, `skills/sweep-it/LENSES.md:40-49`, `skills/review-it/SMELLS.md:18,20`): a lane M audit can raise the same pass-through finding from Standards and Architecture. Keep them in design-it and link. New evidence for T39: `prove-it/VALIDATE.md` is doubt-it rebuilt, and no skill calls doubt-it.

20. **The lifecycle stops at a local commit** (`skills/ship-it/SKILL.md:47-49,97-98`): no skill owns push or PR (body, protected-branch check), version headings in the changelog, or carrying out the rollback note ship-it writes. T24 covers PR feedback only.

8 smaller findings left out: `DO_IT_HOOK_TIMEOUT` not validated (NaN timeout); `work.mjs show/event/close` do not validate the id the way `new` does; config's repo root and git's top-level can disagree; `isMain` copied 5 times; the plan parser keeps ~120 lines for flow-map input that only old (now deleted) plans used; small it-core restatements in build-it/STANDARDS.md, do-it and grill-it; `docs/reference-audit/` has no config key; a hooks.json/claude.mjs event-name mismatch would silently disable the guard.

## Architecture notes

- `skills/do-it/scripts/state.mjs` + `work.mjs`: one module split in two; the lane, phase-ownership and close rules sit in the CLI. Worth `/deepen-it skills/do-it/scripts`.
- `state.mjs`: four modules in one file (YAML subset parser, writer, transitions, roadmap slices); roadmap has one caller.
- Frontmatter handling: four shallow copies; a shared module earns its place (deletion test: CRLF and quoting reappear in every caller).
- Host adapters (`hooks/claude.mjs`, `.opencode/plugins/do-it.mjs`): each owns its own error policy; a shared guarded decision layer is T42 and would fix finding 2 at the seam.

Verdict: fix 1, 2 and 3 first (all in the hooks and config trust path), then 4, 5 and 7 (state that has no git copy).
Lean: roughly -150 to -250 lines possible (duplicate diff loops, frontmatter copies, legacy parser paths, DESIGN.md copies of STATE.md); 0 dependencies to remove.
Not checked: Windows behaviour (finding 17 is from reading, not running); OpenCode 2 API; behaviour of the skills under a real agent run (T2); finding 1 end to end against a real Jira.
