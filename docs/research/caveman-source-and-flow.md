# Caveman: source and flow

Answer: Caveman 4.x ships its voice as three self-contained skills (caveman, ultracave, megacave), tracks the mode per session in small files written by Node hooks, and re-injects the full skill at SessionStart, on mode switch, to subagents, and as a short reminder every prompt. The "read less" tools are a separate Go engine and proxy with measured but narrow results. Confidence: high for the hook and skill mechanics (read in full), medium for the engine and proxy (sampled, not read end to end).
Versions: commit `bad48a0e1df55e05e3f52249afa35ecc1909ee76` (2026-10-17, 60 commits after tag v4.0.1); `.claude-plugin/plugin.json` and `package.json` both say 4.0.1. Checked: 2026-10-21.

Method: shallow clone, files read only, nothing executed. Links are pinned to that SHA. Base: `https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/`. Paths below are relative to it.

## Findings

### 1. Voice rules and the text that enforces them

- The voice is defined once, in `skills/caveman/SKILL.md`. Its thesis line is "Respond terse like smart caveman. All technical substance stay. Only fluff die." and it adds "Caveman is a voice, not broken grammar." ([skills/caveman/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman/SKILL.md), lines 11-13)
- Nine numbered rules, each a `### N.` heading: 1 Answer first (pattern `[thing] [action] [reason]. [next step].`); 2 Kill ceremony ("No greeting, hedging, pleasantries, recap, or closer", no "Sure!", "Let me", "I'll now", no just/really/basically/actually/simply); 3 Short word ("fix" not "implement a solution for"; no invented abbreviations like cfg, impl, fn; "No arrows"); 4 "Articles optional, meaning never" ("Never drop not/never/no/only/except. Numbers and units exact."); 5 One idea per sentence ("ASD-STE100 is the floor: 20 words max, active voice, imperative for instructions, one term per thing"; "Compression and clarity conflict? Clarity wins."); 6 Payload verbatim; 7 Tool runs: bounded status; 8 User's language; 9 Never perform caveman. ([skills/caveman/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman/SKILL.md), lines 28-70)
- Rule 6 verbatim scope: "Code blocks unchanged. Commands, paths, API names exact. Errors quoted exact, shortest decisive line only. Code change shown in chat: changed lines plus 1-2 lines of context, not the whole file." Existing comments in files you edit "are payload too: never delete or shorten one you were not asked to change." ([skills/caveman/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman/SKILL.md), line 58)
- Rule 7 verbatim: "No text between routine calls. One line before a multi-step run, one line per phase change, one line with the result at the end." ([skills/caveman/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman/SKILL.md), line 62)
- Rule 9 verbatim: "No 'caveman mode on', no 'me think', no 'Caveman:' prefix, no normal answer plus caveman copy. No decorative tables or emoji. Never add a word to sound caveman. Caveman phrasing not shorter than plain? Use plain." ([skills/caveman/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman/SKILL.md), line 70)
- A four-item "Pre-send check" ends the skill: delete an announcing first sentence, delete a recapping or help-offering last sentence, confirm every not/never/no/only and every code span, path, number and error is verbatim, make any two-reading sentence a full sentence. ([skills/caveman/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman/SKILL.md), lines 84-89)
- The "Why" block gives the stated priority: "A dropped negation costs more than every token saved. Clarity beats compression." ([skills/caveman/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman/SKILL.md), line 26)
- `skills/ultracave/SKILL.md` is a separate full skill: thesis plus "Then cut again.", "Ultracave is caveman with the grammar stripped. Payload only.", six rules (Fragments, One word when one word is enough, Each fact once, Cut conjunctions only when order survives, Tool runs "One line in, one line out", Never perform) and a Floor ("Never cut: code, commands, paths, API names, error strings (verbatim). not/never/no/only/except. Numbers and units. The user's language."). Frontmatter has `disable-model-invocation: true`. ([skills/ultracave/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/ultracave/SKILL.md), lines 1-63)
- `skills/megacave/SKILL.md` answers in Classical Chinese (文言文): "以文言答。技術之實皆存，唯贅言去之。" Code, commands, paths, errors stay in original script; negation (不, 非, 勿, 未, 毋) never cut; "Token savings are small and noisy; never claim them." Also `disable-model-invocation: true`. ([skills/megacave/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/megacave/SKILL.md), lines 1-65)
- The always-on rule file for IDE hosts is generated from the skill: thesis line, each `### N.` headline with the first sentence of its body, plus a fixed tail (Switch, Stop, Auto-Clarity, Boundaries, Floor). ([skills/activation-rule.mjs](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/activation-rule.mjs), lines 1-35; output in [src/rules/caveman-activate.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/rules/caveman-activate.md))
- Sibling one-shot skills: `caveman-commit` (Conventional Commits, subject at most 50 chars with hard cap 72, no trailing period, body only for non-obvious why, breaking changes, migrations, linked issues; "Generated with Claude Code" or any AI attribution is banned "unless the user's own rule requires an Assisted-by/AI-attribution trailer"); `caveman-review` (`L<line>: <problem>. <fix>.` with severity prefixes bug, risk, nit, question). ([skills/caveman-commit/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman-commit/SKILL.md), Rules and "What NEVER goes in"; [skills/caveman-review/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman-review/SKILL.md), Rules)
- The per-turn reminder text (not in any SKILL.md) is built in the tracker: "CAVEMAN MODE ACTIVE (<mode>). <thesis line> Answer only what was asked: no unrequested background, lists, examples, walkthroughs, or follow-up offers; give code, steps, or warnings when the task needs them. Security warnings, irreversible actions, multi-step order: normal prose. Technical terms, code, commands, paths, and errors stay exact." ([src/hooks/caveman-mode-tracker.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-mode-tracker.js), `reinforcementForMode`)

### 2. Flow: activation, state, hooks, intensity, off

- Intensity levels no longer exist as levels. The six levels (lite, full, ultra, wenyan variants) were replaced in 3.1.0 by three skills that map 1:1 to stored modes: `caveman`, `ultracave`, `megacave`, plus one-shots `commit`, `review`, `compress`, and `off`. Legacy values map forward on every read (`lite`/`full` to caveman, `ultra` to ultracave, `wenyan*` to megacave); writes never emit them. ([src/hooks/caveman-config.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-config.js), lines 39-66; [docs/technical/three-skills-refactor.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/docs/technical/three-skills-refactor.md), Goal and Mode model)
- The difference between levels is the entire skill file that gets injected. SessionStart reads `skills/<mode>/SKILL.md`, strips frontmatter, and emits the whole body under the banner `CAVEMAN MODE ACTIVE — mode: <mode>`, then the line `Switch: /caveman, /ultracave, /megacave. Off: "stop caveman" or "normal mode".` ([src/hooks/caveman-activate.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-activate.js), `buildRuleset`; [src/hooks/caveman-config.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-config.js), `loadRuleset` line 811, `rulesetBanner`)
- Skill lookup order: `$CLAUDE_PLUGIN_ROOT/skills/<id>/SKILL.md`, then `../../skills/<id>/`, then `../skills/<id>/`. With no skill file found it falls back to a hard-coded ruleset of the nine rule headlines. ([src/hooks/caveman-config.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-config.js), `skillPathCandidates`, `fallbackRuleset` line 840)
- Hooks registered by the plugin: SessionStart, SubagentStart (`--subagent`), UserPromptSubmit, SessionEnd (stats `--record`). All run `node` scripts and exit 0 if node is missing. ([.claude-plugin/plugin.json](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/.claude-plugin/plugin.json), `hooks`)
- Default mode resolution order: env `CAVEMAN_DEFAULT_MODE`, then repo-local `.caveman/config.json` or `.caveman.json` (walked up from cwd, first file that names a `defaultMode`), then user config (`$XDG_CONFIG_HOME/caveman/config.json`, `~/.config/caveman/config.json`, `%APPDATA%` on Windows), then `caveman`. `manual` is a startup policy (sessions start off, explicit `/caveman` activates); `off` suppresses automatic and bare-command activation. ([src/hooks/caveman-config.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-config.js), header comment and `getDefaultMode` line 174; [skills/caveman-help/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman-help/SKILL.md), "Configure Default Mode")
- Headless `claude -p` and Agent SDK sessions (`CLAUDE_CODE_ENTRYPOINT` starting `sdk-`) start under `manual` unless `CAVEMAN_DEFAULT_MODE` is set. ([src/hooks/caveman-activate.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-activate.js), `startMode`)
- Mode state is per session: `$CLAUDE_CONFIG_DIR/.caveman-sessions/<session_id>.mode` (plus `.prev` for one-shot restore), keyed by the `session_id` in the hook payload. `$CLAUDE_CONFIG_DIR/.caveman-active` remains as a last-write-wins mirror that never holds the literal `off` (deactivation deletes it). Session ids are whitelisted before use in a path. ([src/hooks/caveman-config.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-config.js), lines 509-640; [src/hooks/README.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/README.md), "Where the mode lives")
- Flag files are written atomically via temp file and rename, with `O_NOFOLLOW`, mode 0600, and read with a 64-byte cap and a mode whitelist, so a symlinked flag cannot inject bytes into context or the statusline. ([src/hooks/caveman-config.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-config.js), `safeWriteFlag` line 225, `MAX_FLAG_BYTES` line 408)
- Transitions are also appended to `$CLAUDE_CONFIG_DIR/.caveman-mode-log.jsonl` for stats. ([src/hooks/caveman-config.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-config.js), `MODE_LOG_BASENAME` line 714)
- SessionStart fires for every source (startup, resume, clear, compact, fork). Only `startup` and `clear` re-derive the configured default; the others read the stored literal value, so "stop caveman" followed by compaction stays off, and an active mode is re-injected after compaction because compaction prunes the rules. ([src/hooks/caveman-activate.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-activate.js), `RESET_SOURCES`, `run`; [src/hooks/README.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/README.md), "Why source matters")
- When the resolved mode is `off` or `manual`, SessionStart records the transition, writes durable `off`, prints `OK`, and injects nothing. One-shot modes get one line: `CAVEMAN MODE ACTIVE — mode: <m>. Behavior defined by /caveman-<m> skill.` ([src/hooks/caveman-activate.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-activate.js), `run`)
- SubagentStart: the same script with `--subagent` prints `hookSpecificOutput.additionalContext` carrying this session's active skill body. It is read-only, prints nothing when the session is `off`, in a one-shot mode, for agent types matching `cavecrew-`, or when the repo `defaultMode` is `off`. ([src/hooks/caveman-activate.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-activate.js), `runSubagent`; tested in [tests/hooks/subagent-start.test.mjs](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/tests/hooks/subagent-start.test.mjs))
- UserPromptSubmit does four things in order: skip scheduled-task prompts entirely (`<scheduled-task`); unwrap Claude Code slash-command envelopes (`<command-name>`, `<command-args>`); handle `/caveman-stats` by running the stats script and asking the model to print the block verbatim; parse a mode change. Then it emits one `additionalContext` combining (a) a notice if a `/caveman` argument was not recognized, (b) the full new skill body if the mode genuinely changed, (c) the per-turn reminder. ([src/hooks/caveman-mode-tracker.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-mode-tracker.js), `handle`)
- The per-turn reminder is skipped for one-shot modes and when a repo config sets `defaultMode: "off"`. The source comment says it exists because "models lose it when other plugins inject competing style instructions every turn." ([src/hooks/caveman-mode-tracker.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-mode-tracker.js), comment "Per-turn reinforcement")
- One-shot modes (`commit`, `review`, `compress`): the prose mode displaced is saved to `.prev`, and the next ordinary prompt restores it (or restores off). ([src/hooks/caveman-mode-tracker.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-mode-tracker.js), "One-shot restore (#599)")
- Parser, slash side: `/caveman` (default mode), `/caveman off|stop|disable` clears, `/caveman status` reports, `/caveman ultra|wenyan|lite|full` map through the legacy table, `/ultracave` and `/megacave` (also `/caveman:`-namespaced) set their modes. An unknown argument is never echoed and never changes the mode. ([src/hooks/caveman-parse.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-parse.js), lines 173-207, 309-337)
- Parser, natural-language side. Off (checked first, highest priority): `stop|disable|deactivate|quit|exit|kill [the] caveman`, `caveman [mode] off|stop|disable[d]`, `turn off [the] caveman`, `normal mode` when prompt-initial or with the word caveman. Quoted spans in `"` or backticks are blanked before matching, and prompts starting with `/` skip natural-language matching. On: verb phrases (`activate|enable|start|turn on|use|switch to|want|give me` plus a determiner whitelist plus `caveman`), `talk like [a|an|the] caveman`, `caveman mode on|please|now`, a bare `caveman`, and brevity phrases (`less tokens`, `fewer tokens`, `be brief`, `be terse`, `shorter answers`, not when followed by in/for/on/about/when/during/with). Activation is suppressed for questions and for a negator earlier in the same clause. Natural-language activation sets the default mode, not a chosen level. ([src/hooks/caveman-parse.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-parse.js), lines 94-170, 232-306)
- "Stop caveman" stores a durable `off` for that session (literal `off` in the session file, mirror deleted, `.prev` cleared). It is not a global switch and subagents stay quiet afterwards. ([src/hooks/caveman-mode-tracker.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-mode-tracker.js), `change.action === 'clear'` branch; [src/hooks/caveman-config.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-config.js), `writeSessionMode` line 615)
- Statusline: `caveman-statusline.sh` reads `session_id` from stdin JSON (1 second read ceiling, integer because macOS bash 3.2), reads that session's `.mode` file (else the mirror), refuses symlinks, caps at 64 bytes, strips to `[a-z0-9-]`, prints `[CAVEMAN]`, `[ULTRACAVE]`, `[MEGACAVE]` or `[CAVEMAN:COMMIT]` etc. in orange, and prints nothing for `off`. It shows mode only. ([src/hooks/caveman-statusline.sh](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-statusline.sh), whole file)
- The SessionStart hook also nudges the model to set up the statusline once (marker `.caveman-nudge-shown`), and offers a repair when the configured script is missing or outdated. That text is appended to the injected context. ([src/hooks/caveman-activate.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-activate.js), "Detect missing statusline config")
- Other hosts: OpenCode plugin, Codex SessionStart script, Cursor and Copilot host-session-start script reuse the same config and parser. Not read in detail. ([CLAUDE.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/CLAUDE.md), "File structure" table and `caveman-host-session-start.js` section)
- `/caveman status` is answered by the tracker injecting "Report this status verbatim without changing mode: Caveman mode: <mode|off>". Hosts without hooks answer from conversation and append "(not tracked by this host)". ([src/hooks/caveman-mode-tracker.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-mode-tracker.js), status branch; [skills/caveman/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman/SKILL.md), line 19)
- Inference: the design relies on three layers of repetition (full skill at SessionStart and on switch, a one-paragraph reminder on every prompt, the same skill again at each subagent start). The per-prompt reminder is the cost the HONEST-NUMBERS page does not itemize; no file measures it.

### 3. cavecrew subagents

- Three agent files, auto-discovered from `agents/`: `cavecrew-investigator` (frontmatter `model: haiku`), `cavecrew-reviewer` (`model: haiku`), `cavecrew-builder` (no `model:` line, so the session default). None of the three has a `tools:` field. ([agents/cavecrew-investigator.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/agents/cavecrew-investigator.md), [agents/cavecrew-builder.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/agents/cavecrew-builder.md), [agents/cavecrew-reviewer.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/agents/cavecrew-reviewer.md), frontmatter; confirmed no `tools:` line by grep)
- Inference: "read-only", "No `Bash` available" (builder) and "`Bash` only for git diff" (reviewer) are prose in the agent body, not frontmatter restrictions, so they are model-obeyed rather than enforced.
- Each agent body opens with "Ultracave voice" and the rule "Tool runs: one status line in, one out; nothing between routine calls." Each has an Auto-clarity section: plain English for security warnings and destructive operations, then resume. ([agents/cavecrew-investigator.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/agents/cavecrew-investigator.md), lines 11 and 38-40; same pattern in the other two)
- Investigator report format: rows `<path:line> — `<symbol>` — <≤6 word note>`; one-word group headers (Defs, Refs, Callers, Tests, Imports, Sites) when 3 or more rows; single hit is one line with no header; zero hits is `No match.`; last line totals (omitted for 0 or 1). Refusals: `Read-only. Spawn cavecrew-builder.` ([agents/cavecrew-investigator.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/agents/cavecrew-investigator.md), Output, Refusals)
- Builder: scope "1 file ideal. 2 OK. 3+ → refuse." Edits existing files only, no new abstractions, no drive-by refactors, no comment additions. Workflow Read, Edit smallest diff, re-Read, receipt. Receipt: `<path:line-range> — <change ≤10 words>.` per edit plus `verified: <re-read OK | mismatch @ path:line>.` Terminal-token refusals: `too-big. split: <n one-line tasks>.`, `needs-confirm. op: <command>.`, `ambiguous. ask: <one question>.`, `regressed. revert path:line. cause: <fragment>.` ([agents/cavecrew-builder.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/agents/cavecrew-builder.md), Scope, Workflow, Output, Refusals)
- Reviewer: `path:line: <emoji> <severity>: <problem>. <fix>.` with tiers bug, risk, nit (only if the user asked for thorough), question; zero findings is `No issues.`; sorted by file then ascending line; final line `totals: N bug N risk N nit N question` (written with the emoji). No praise, no refactor proposals; needs more context means append `(see L<n> in <file>)`. Security findings get a plain-English first sentence, then the terse fix line. ([agents/cavecrew-reviewer.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/agents/cavecrew-reviewer.md), Severity, Output, Boundaries, Auto-clarity)
- The main agent is told how to use them by `skills/cavecrew/SKILL.md`, whose description is the trigger. It carries a task-to-agent table (locate, edit of at most 2 files, diff review; new feature, 3+ files, or one-line answers stay on the main thread or vanilla `Explore`/`Code Reviewer`), the rule of thumb "if you'd want the subagent's output in 1/3 the tokens, pick cavecrew. If you'd want prose, pick vanilla.", the three output contracts, and chains: locate then fix then verify; parallel scout with 2-3 investigators in one message; single-shot edit skipping the investigator. ([skills/cavecrew/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/cavecrew/SKILL.md), lines 11-73)
- "What NOT to do" list: no builder when the file is unknown, no investigator-to-builder chain for a 5-file refactor, no "general feedback" from the reviewer, and "If a human will read it directly, paraphrase." ([skills/cavecrew/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/cavecrew/SKILL.md), lines 68-73)
- The SubagentStart hook deliberately skips `cavecrew-*` agents because they carry their own voice; every other subagent gets the session's active skill injected. ([src/hooks/caveman-activate.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-activate.js), `runSubagent`)
- Model pinning without editing the agent files: env vars `CAVECREW_REVIEWER_MODEL`, `CAVECREW_BUILDER_MODEL`, `CAVECREW_INVESTIGATOR_MODEL` patch the installed agent's `model:` line at SessionStart (values with control characters ignored; a plugin update can overwrite the patch). ([src/hooks/cavecrew-model-overrides.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/cavecrew-model-overrides.js), lines 1-60; [skills/cavecrew/README.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/cavecrew/README.md), "Model overrides")
- Every `.md` under `agents/` becomes a subagent, so maintainer docs are kept out of that tree; `tests/verify_repo.py` fails if extra markdown appears. ([CLAUDE.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/CLAUDE.md), "agents/*.md is auto-discovered too")

### 4. Compressed vs verbatim, and auto-clarity triggers

- Compressed: the assistant's own chat prose (articles optional, no ceremony, fragments allowed, 20-word sentences). Verbatim: code blocks, commands, paths, API names, numbers and units, quoted errors (shortest decisive line), negations, the user's language, and existing code comments you did not change. ([skills/caveman/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman/SKILL.md), rules 4, 6, 8)
- Written normally, not caveman: everything persisted outside chat: "code, comments, commits, docs, issues, PRs, tickets, memory files, third-party messages." `/caveman-compress` is the stated exception. ([skills/caveman/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman/SKILL.md), line 80)
- Exact "When to break the rules" triggers (plain prose, then resume): 1 security warning; 2 irreversible action ("Confirm in full sentences first"); 3 step order a fragment could scramble; 4 user confused or repeats the question; 5 anything persisted outside chat; 6 harness asks for a status line or confirmation ("Harness decides *when* you speak, caveman decides *how*"); 7 you ask the user a question or offer options. ([skills/caveman/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman/SKILL.md), lines 72-82)
- Ultracave and megacave add "Any fragment with two readings" (megacave: "Any clause with two readings", falling back to 白話) to that list. ([skills/ultracave/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/ultracave/SKILL.md), line 59; [skills/megacave/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/megacave/SKILL.md), line 61)
- Commit skill: always include a body for breaking changes, security fixes, data migrations, reverts. Review skill: drop terse mode for security findings, architectural disagreements, and a new author who needs the why. ([skills/caveman-commit/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman-commit/SKILL.md), Auto-Clarity; [skills/caveman-review/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman-review/SKILL.md), Auto-Clarity)
- There is no mechanical trigger: auto-clarity is an instruction the model applies by judgment. The hooks never detect a security or destructive context. (Inference from the hooks: none inspects model output or tool calls for safety content; [src/hooks/caveman-mode-tracker.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-mode-tracker.js) only reads user prompts.)

### 5. Read-less tooling

Four different things share the word "shrink" or "compress":

- `caveman-compress` (skill plus Python scripts) rewrites a natural-language memory file (`.md`, `.mdc`, `.txt`, `.rst`, `.typ`, `.typst`, `.tex`, extensionless) using a model call, then validates locally. It sends the file text to the configured provider, refuses secret-looking filenames and files over 500KB, backs the original up out of tree (`$XDG_DATA_HOME/caveman-compress/backups/<parent-dir-name>/`), retries up to 2 times with targeted fixes, and leaves the original untouched if validation still fails. ([skills/caveman-compress/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman-compress/SKILL.md), Purpose, Process, Boundaries; [skills/caveman-compress/README.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman-compress/README.md), "How It Work")
- Its validator checks headings (changed heading text is an error), fenced and indented code blocks, URLs, file paths, bullet counts and inline code. It does not check meaning. ([skills/caveman-compress/scripts/validate.py](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman-compress/scripts/validate.py), `validate_*` functions)
- Measured result: 5 fixture pairs, 6,198 to 4,138 tiktoken o200k tokens (33.2% total, 22.8% to 49.1% per file). The README states "result does not prove semantic equivalence on other files or models." ([skills/caveman-compress/README.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman-compress/README.md), "Benchmarks"; fixtures in [tests/caveman-compress/](https://github.com/JuliusBrussee/caveman/tree/bad48a0e1df55e05e3f52249afa35ecc1909ee76/tests/caveman-compress))
- Engine (Go): `engine/` detects shape and picks one of 16 compressors; every compressor is class S4 (lossy). A lossy result is emitted only if the exact original is stored in the local recovery store (CCR, SQLite at `~/.caveman/ccr.db`, handles `ccr_<hex>`); on any parse error, larger result, unknown mode, or store failure the original bytes pass through. Token counts use an offline o200k_base counter, labeled `inferred`. ([docs/technical/engine.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/docs/technical/engine.md), "Compression pipeline", "Compressor registry", "Recovery requirement"; [docs/technical/context-recovery.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/docs/technical/context-recovery.md), "Handles", "Capacity behavior")
- Logs: keeps the first 2 and last 2 lines, every line matching ERROR/FATAL/PANIC/EXCEPTION/TRACEBACK/FAIL/WARN/CRIT/ALERT/EMERG, stack-frame lines, `.go:<n>`, "caused by", and query-relevant lines (BM25, up to 16, threshold 0.30); runs of other lines become `… N lines elided (caveman): <summary> …`. Fewer than 4 lines or invalid UTF-8 passes through. ([engine/compressors/log.go](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/engine/compressors/log.go), `importantLineRe`, `NewLog`, `compress`)
- JSON: arrays longer than 8 are eligible to collapse; every object key and the structure stay; keeps first 3 and last 2 elements, error-state elements (keys such as error, message, stack; values such as failed, timeout, denied), median/MAD anomalies (|z| at least 2.0), change-points (CUSUM), and query-relevant items (max 50). Collapsed runs become a `__caveman_elided__` marker with `__caveman_invariants__` facts computed from the dropped elements. ([engine/compressors/json.go](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/engine/compressors/json.go), lines 17-62)
- CSV, TSV and Markdown tables: at least 12 rows to compress, keeps header, first 3 and last 2 rows, rows matching ERROR/FAIL/DENIED/REJECTED and similar, and query-relevant rows (limit 24); dropped rows become `… N rows elided (caveman): <summary> …`. ([engine/compressors/tabular.go](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/engine/compressors/tabular.go), `NewTabular`, `tabularImportantRe`)
- YAML, TOML, INI ("config"): at least 14 lines, keeps head 3, tail 2, lines containing ERROR/WARNING/SECURITY/SECRET/TOKEN/PASSWORD/DENIED/ROLLBACK and similar, and query-relevant lines (limit 16). ([engine/compressors/config.go](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/engine/compressors/config.go), `NewConfig`, `configImportantRe`)
- Test output: JUnit XML, pytest-json-report and Jest JSON become a text summary with counts and every failure; plain test-runner text goes through the terminal compressor instead. ([engine/compressors/testreport.go](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/engine/compressors/testreport.go), lines 14-20; [engine/compressors/terminal.go](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/engine/compressors/terminal.go), whole file)
- Terminal compressor (used by `caveman shrink`): strips ANSI escapes, collapses carriage-return progress redraws to the last frame, keeps first 3 and last 3 lines plus any line matching error/fail/panic/traceback/exception types, stack frames, `file:line:col:` locations, or `exit status N`; elides the rest. ([engine/compressors/terminal.go](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/engine/compressors/terminal.go), `termImportantRe`, `elideMiddle`)
- Elision is deterministic and idempotent by design (own markers are kept on later passes) so it does not break the provider prefix cache; a one-per-payload "contract line" tells the model how to read an elided view. ([engine/compressors/log.go](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/engine/compressors/log.go), comments in `compress`; [engine/compressors/json.go](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/engine/compressors/json.go), `ElidedNoteKey`)
- `caveman shrink -- <cmd>` runs the command, merges stdout and stderr in arrival order, runs the terminal compressor, prints the shrunk text plus a footer `‹caveman: shrank · B→A estimated tokens · counter o200k_base · inferred · recover: caveman retrieve <handle>›`, and propagates the exit code. It passes output through unchanged for `--raw`, empty input, input over `CAVE_MAX_SHRINK_BYTES` (default 8 MiB), or any engine problem. ([packages/cli/src/index.ts](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/packages/cli/src/index.ts), `shrink` line 16535, `emitShrunk`; tested in [packages/cli/tests/shrink.runtime.mjs](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/packages/cli/tests/shrink.runtime.mjs), exit-code and fail-open cases)
- The automatic hook (`shrink-hook`, PreToolUse on Bash for Claude Code) rewrites a command to `caveman shrink -- <cmd>` only if the first word is on `SHRINK_ALLOW` (git, cargo, go, npm, pnpm, yarn, pip, pytest, make, jest, vitest, tsc, eslint, mypy, ruff, mvn, gradle, dotnet, grep, rg, find, ls, tree, du, df, ps, docker, kubectl, terraform, helm, aws, gcloud, az, gh and a few more), the command has no pipe, redirect, `&`, `;`, backtick, `$(`, newline, and no follow/watch/interactive flag. It skips listed subcommands (git commit/rebase/mergetool, docker run/exec/attach, kubectl edit/exec/attach, terraform apply/destroy, npm/yarn/pnpm init) anywhere in the argument list. It never sets a permission decision. It does not run for Codex (#1037). It also needs the native profile `full-safe` or `full-max` and the `think.shrink` capability. ([packages/cli/src/index.ts](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/packages/cli/src/index.ts), `SHRINK_ALLOW`, `shouldShrink`, `shrinkHook` line 16739)
- `caveman-shrink` (Go `shrink/`, npm launcher) compresses MCP or OpenAI tool catalogs: keeps names, parameters, enums, required, defaults, const and `$ref` targets byte for byte, drops annotations, shortens long descriptions while keeping constraint sentences. Its own README says description reduction "is model-visible and lossy" and structural preservation does not guarantee the model picks the same tool. Input cap 32 MiB. ([shrink/README.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/shrink/README.md), opening and "Guarantees"; [docs/technical/local-tools.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/docs/technical/local-tools.md), "Tool-catalog shrinker")
- A second, older `caveman-shrink` (Node, `src/mcp-servers/caveman-shrink/`, v0.1.1, "Pre-1.0") is a stdio MCP proxy that applies regex deletion of articles, filler, pleasantries and hedges to `description` fields of `tools/list`, `prompts/list`, `resources/list`. It leaves `tools/call` responses unchanged. It skips text containing CJK. ([src/mcp-servers/caveman-shrink/README.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/mcp-servers/caveman-shrink/README.md), "What it does NOT touch"; [src/mcp-servers/caveman-shrink/compress.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/mcp-servers/caveman-shrink/compress.js), lines 1-60)
- Proxy (`caveman <agent>` wrap): for Anthropic `/v1/messages` the compressible fields are declared as "cache-cold user text and tool_result output"; it never collects the top-level system field, tools, frozen (cache-warm) messages, assistant messages, or non-text blocks, and byte-splices replacements into the original request. Recovery tool results are never recompressed. A transformed request that gets a 4xx is retried once with the original bytes, except a 429 with Retry-After. ([proxy/providers/compression_coverage.go](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/proxy/providers/compression_coverage.go), lines 30-33; [proxy/providers/anthropic/content_compress.go](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/proxy/providers/anthropic/content_compress.go), `ExtractCompressible`, `collectAnthropicBlocks`; [proxy/CLAUDE.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/proxy/CLAUDE.md), Gotchas)
- `caveman browse` attaches to Chrome over CDP, captures the accessibility tree, filters by query, compresses, returns action refs and a recovery handle. Its benchmark (Chrome 151, Playwright 1.56.1, o200k, 5 runs): 200-row table, raw AX 398,494 tokens, Playwright ARIA 15,704, caveman full result 13,368, focused result 121 (129.8x smaller than Playwright). ### 6. Agent-to-agent messages, handoffs, conflicts with other style instructions

- Agent-to-agent format rules exist only for cavecrew (section 3): fixed line formats, terminal refusal tokens, "Always file-path-first, line-number-attached, backticked symbols. Safe to grep with `path:\d+`." There is no general rule for handoffs between arbitrary agents beyond the SubagentStart injection of the active voice. ([skills/cavecrew/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/cavecrew/SKILL.md), "Output contracts")
- Rule 5 of the voice ("persisted outside chat ... third-party messages") means a subagent report written to a file or sent to another party is written normally; whether a subagent-to-main report counts as "chat" is not stated. ([skills/caveman/SKILL.md](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/skills/caveman/SKILL.md), line 80)
- Inference: because the SubagentStart hook injects the full skill into every non-cavecrew subagent, a vanilla `Explore` or reviewer subagent will answer in caveman voice, and its report lands in the main context in that voice.
- Conflict handling with other style sources is repetition, not arbitration. The only mechanism is the per-turn reminder, justified in a comment as a counter to "other plugins [that] inject competing style instructions every turn." No file defines precedence between caveman, a project `CLAUDE.md`, or another plugin's output style. ([src/hooks/caveman-mode-tracker.js](https://github.com/JuliusBrussee/caveman/blob/bad48a0e1df55e05e3f52249afa35ecc1909ee76/src/hooks/caveman-mode-tracker.js), comment "Per-turn reinforcement"; searched `src/`, `skills/`, `docs/technical/`, `INSTALL.md`, `CLAUDE.md` for competing, output style, conflict)
- Opt-outs that do exist: repo-local `.caveman.json` or `.caveman/config.json` with `defaultMode: "off"` stops the reminder and the subagent injection (a project can opt out); `manual` default; `<scheduled-task` prompts are never styled; the commit skill defers to the user's own attribution rule.
